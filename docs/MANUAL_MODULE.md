# 현장 장비 매뉴얼

장비 종류 → 모델 → 같은 탭의 사용방법 화면으로 구성한다. 기존 WORKHUB 헤더와 로그인 세션을 재사용한다. 등록·수정·삭제는 기존 자료 관리와 동일하게 관리자만 가능하며 서버에서도 검증한다. 사용방법 화면의 ‘모델·첨부자료 관리 → 모델 목록 썸네일’에서 JPG·PNG·WebP(최대 10MB)를 등록·교체한다. 관리 화면에는 파일명만 표시하며, 이미지 자체는 모델 목록에 표시한다. 썸네일을 삭제하면 미등록 상태로 표시한다.

모델 목록 썸네일은 `purpose=model-cover`, 매뉴얼 장비사진은 `kind=photo, purpose=manual`, 동영상 썸네일은 `kind=thumbnail`로 구분한다. 일반 장비사진은 목록이나 동영상 썸네일로 자동 사용하지 않는다. 기존에 지정한 목록 대표사진은 파일을 보존하면서 model-cover로 한 번 이관한다. 썸네일 교체는 새 파일 저장 후 DB 연결을 변경하고 이전 파일을 정리한다.

홈에서 진입하는 장비 종류 화면은 이름·설명·모델 선택 버튼을 가진 카드 그리드다. 장비 이미지, 자료별 개수, 수정일 및 자료 유형·제조사·정렬 필터는 표시하지 않는다. 모바일에서는 한 열로 표시한다. 파일 선택 창의 focus 복귀 이벤트에서 목록을 자동 새로고침하지 않는다. 이때 파일 입력란이 사라지면 선택 파일의 change 이벤트가 유실되므로 새로고침은 명시적인 화면 이동·변경에만 적용한다.

## 코드 위치

모델 목록 클릭 시 목록 위의 모달 팝업으로 사용방법을 연다. 닫기 또는 Escape로 목록에 복귀하며, 개별 상세 URL도 유지한다. 자료 관리 영역은 위·아래 닫기 버튼으로 숨긴다. 동영상 아래 중복 제목·썸네일 카드 목록은 표시하지 않으며, 영상이 여러 개일 때 재생창 위 선택 메뉴를 제공한다.

- `src/components/manual`: 목록, 상세, 본문 편집, 미디어 조회, 첨부자료 관리
- `src/features/manual`: API와 공통 타입·파일 제한
- `backend/routes/manual.ts`: 인증·권한·감사 로그와 HTTP 연결
- `backend/manual-service.ts`: 모델별 데이터, 본문 버전 충돌, 첨부자료 상태 관리
- `backend/manual-storage.ts`: 스트림 업로드, 파일 검증, 부분 다운로드, 정리 재시도
- `backend/database/manual-schema.ts`: 기존 데이터를 보존하는 반복 가능한 추가 마이그레이션

SQLite에는 본문과 파일 메타데이터만 저장한다. R2 사용 시 원본은 비공개 객체로 저장하며 인증 후 유효기간이 있는 GET URL로 직접 전송한다. 로컬 개발에서는 기존 private storage를 사용한다. GET에는 Range를 유지한 리다이렉트, HEAD에는 객체 메타데이터 응답을 사용한다.

## 등록 제한

영상은 모델당 4개, MP4/H.264 파일당 200MB까지 허용한다. AAC 오디오와 약 3분 길이를 권장하며, 업로드 전에 압축한다. 서버는 MP4 구조와 H.264 표식을 검사하지만 정밀한 전체 스트림 검사나 인코딩은 수행하지 않는다. 영상 썸네일은 브라우저에서 추출하며 등록된 사진으로도 선택할 수 있다.

사진은 JPG·PNG·WebP 파일당 10MB/모델당 30장, PDF는 파일당 20MB/모델당 10개다. 사진은 디코딩 검증, PDF는 헤더·종료 표식 검증을 적용한다. PDF의 전체 문서 구조나 악성코드 검사는 별도 기능이다.

첨부파일 교체는 새 파일 등록 후 기존 파일 삭제로 처리한다. 업로드 예약, 전송, 검증, 저장소 저장 후에만 자료를 공개한다. 실패·삭제된 객체는 SQLite 정리 대장에 남겨 재시도한다. 삭제는 화면과 API에서 즉시 숨기고 물리 파일 정리를 별도로 재시도한다.

## 로컬 검증

`npm run dev:manual-preview`는 `http://localhost:3002/manual`에 별도 테스트 사이트를 연다. DB와 파일은 `.tmp/manual-preview`에만 저장하며 테스트 모델·3초 샘플 영상·사진·PDF도 여기에만 등록한다. 일반 실행이나 마이그레이션에는 예시 모델을 등록하지 않는다.

테스트 계정: 관리자 `user-5` / `1234`, 조회 사용자 `user-1` / `1234`. 기존 로컬 테스트 계정이며 운영 계정과 관계없다.

`npm run test:manual`, `npm run test:manual-r2`는 `.tmp/test-runs`의 격리 DB를 사용한다. R2 테스트는 SDK 모의 저장소를 사용하며 실제 클라우드에 접근하지 않는다. `npm run lint`, `npm run build`로 타입·빌드 및 보호된 기존 기능 범위를 확인한다.

실제 R2의 CORS/Range 전송, 현장 3분 영상의 코덱 호환성 및 iOS·Android 실기기의 전체 화면은 운영 배포 전에 별도 테스트해야 한다. 현재 검증은 로컬 브라우저와 390px 화면, 3초 H.264/AAC 영상, 로컬 Range 및 R2 어댑터 모의 테스트까지다. 배포는 수행하지 않았다.

## 사진 자동 압축 (2026-10-15)

사진 선택 시 브라우저에서 설명용은 긴 변 2000px, 목록/동영상 썸네일은 800px, 품질 0.85로 변환한다. 작은 사진은 확대하지 않는다. WebP 실제 출력 MIME을 확인하며 미지원 시 불투명 사진은 JPG, 투명 사진은 PNG로 대체한다. 변환 결과가 원본보다 작을 때만 채택한다. 원본은 최대 10MB/4천만 화소/한 변 16384px, 업로드 결과는 기존 모델별 제한(사진 10MB, 영상 썸네일 2MB)을 적용한다.

`photo-compression.ts`에서 디코딩 전 헤더 크기 검사, EXIF 회전, 투명도 검사, 작업 직렬화를 처리한다. `ManualPhotoInput`은 미리보기·용량·감소율, 압축 중 상태, 재선택 취소와 인코딩 실패 시 원본 선택을 제공한다. 기존 자료와 자재 기능에는 적용하지 않는다. R2 매뉴얼 객체는 명시적으로 Standard 클래스로 업로드한다.

브라우저 검사는 격리 미리보기의 `/backend/tests/manual-photo.browser.html`에서 검사 실행 버튼으로 수행한다. 이 페이지와 테스트 자료는 Vite 운영 빌드에 포함되지 않으며 운영 API에서 제공하지 않는다. 원본이 800/2000px를 넘더라도 재인코딩 이점이 없으면 원본 유지 규칙이 우선한다. 현재 사진 선택은 한 번에 한 장이며 각 선택은 직렬 처리한다.

운영 마이그레이션 전 `PRESTART_DATABASE_BACKUP_TAG`를 배포 커밋 SHA로 설정한다. 기존 `npm start`의 백업 스크립트가 `/var/data/backups/catv-predeploy-<SHA>.sqlite`를 VACUUM INTO로 생성하고 integrity_check 통과 후 서버를 시작한다. 실패하면 마이그레이션을 시작하지 않는다. 복구 시 서비스 쓰기를 중지하고 백업 integrity_check 후 DB/WAL/SHM을 일관되게 복원한다. 단순 코드 롤백은 신규 매뉴얼 테이블을 삭제하지 않는다.

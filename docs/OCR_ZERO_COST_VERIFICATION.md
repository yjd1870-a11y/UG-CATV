# 업무이관 OCR 무비용 검증 보고서

## 결론

- 실행 엔진: 브라우저 내 Tesseract.js `kor+eng` LSTM
- 실행 위치: 사용자 단말 브라우저
- 런타임 자산: 애플리케이션의 `/ocr/*` 경로에서 자체 제공
- 외부 OCR API, API 키, 유료 SaaS, 추가 Render 서비스: 사용하지 않음
- 예상 추가 월 과금: 0원

## 사진 처리 경계

OCR용 원본은 브라우저의 `File`/`ImageBitmap`/`canvas` 메모리에서만 처리한다.
등록 API에는 OCR용 파일 또는 Base64를 넣지 않는다. 미리보기 `Blob URL`은 취소,
닫기, 재선택, 컴포넌트 해제 시 폐기한다. 기존 접수 증빙사진은 사용자가 별도
입력에서 선택한 경우에만 기존 비공개 사진 저장 경로로 전송한다.

기존 서버 OCR 엔드포인트는 요청 본문을 처리하기 전에 `410 BROWSER_OCR_ONLY`로
종료하므로 이전 클라이언트가 OCR 원본을 서버에 보내 처리하는 흐름도 사용할 수 없다.

## 정확도 보강

해상도, 밝기, 대비, 흐림, 반사, 암부 비율을 OCR 전에 검사한다. 운영 화면에는
HNS 지점명과 고객주소 2개 항목만 자동 입력하고 사용자가 저장 전에 확인·수정한다.
점검요청일은 OCR하지 않고 한국시간 등록일을 기본값으로 제공하며 사용자가 직접 수정할 수 있다.
점검작업업체는 `유지텔레컴`으로 고정하며 매체구분은 신규 등록 UI와 OCR에서 제외한다.
OCR 원문과 상세 파싱 결과는 서버 또는 DB에 저장하지 않는다. 나머지 상세 항목은 완료 전
증빙사진으로 확인한다.

한글·영문 학습데이터도 `/ocr/lang-v9/*.traineddata.gz`에서 자체 제공하며 CDN을 호출하지 않는다.
4K 전체 사진과 레이아웃 블록을 인식하지 않고 고정 요청등록 양식에서 지점명과
고객주소 값 행만 비율 좌표로 잘라 인식한다. JPEG EXIF 방향을 먼저 정규화하고 화면 촬영의
모아레를 축소·평균화한 뒤, 지점명의 한글 핵심 영역과 주소 끝부분을 각각 확대 재검사한다.
과거 지점 방향(동·서·남·북부)은 4개 현재 지점명으로 통합하고, 고객주소의 시·군 매핑을
OCR 지점명보다 우선한다. 주소 끝의 짧은 영문 잡음은 제거한다.
주소의 도로명·건물번호·괄호 구조가 서로 충돌하면 자동 확정하지 않는다. 사용자가 처리 중 새 사진을
선택하면 이전 Worker를 취소하고 최신 사진으로 즉시 교체하므로 중복 작업 오류를 표시하지 않는다.

## 운영상 제한 및 다음 검증

2026-09-03에 제공된 화면 촬영 원본(4032×3024, EXIF 회전 포함)으로 브라우저 실검증을
완료했다. 기존 `HNS수원서부지점`은 `HNS수원지점`으로 정규화되며, 지역 `수원`과
`경기 수원시 장안구 송정로76번길 58 (정자동)`이 자동 입력됐다. 점검요청일은 사진의
`2026-09-01`을 사용하지 않고 등록일을 기본값으로 사용한다. 대괄호 지번처럼
모아레로 확정하지 못한 보조 정보는 임의 생성하지 않고 기본 도로명 주소만 채운다.
실제 처리 시간은 최초 모델 캐시 여부와 단말 성능에 따라 달라지며 나머지 항목은 OCR 대상이 아니다.
화면 모아레가 강한 하단의 빈 측정값 템플릿(측정주파수/상·하향 레벨/MER)은
자동입력 대상이 아니며 증빙사진에서 확인한다. 취소 후 OCR 사진과 브라우저의
인식 결과가 모두 제거되는 것도 확인했다.

기본 임계값은 `quality.ts` 한 곳에서 조정 가능하다.
PaddleOCR.js 공식 브라우저 패키지는 한국어 내장 모델을 제공하지 않아 채택하지 않았다.
향후 Paddle 한국어 ONNX 모델을 직접 준비할 경우에도 라이선스, 브라우저 용량,
저사양 단말 처리시간과 실제 표본 정확도를 확인하기 전에는 운영 기본 엔진으로 전환하지 않는다.

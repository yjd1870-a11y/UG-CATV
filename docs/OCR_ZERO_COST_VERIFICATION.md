# 업무이관 OCR 무비용 검증 보고서

## 결론

- 실행 엔진: 브라우저 내 Tesseract.js `kor+eng` LSTM
- 실행 위치: 사용자 단말 브라우저
- 런타임 자산: 애플리케이션의 `/ocr/*` 경로에서 자체 제공
- 외부 OCR API, API 키, 유료 SaaS, 추가 Render 서비스: 사용하지 않음
- 예상 추가 월 과금: 0원

## 사진 처리 경계

OCR용 원본은 브라우저의 `File`/`ImageBitmap`/`canvas` 메모리에서만 처리한다.
등록 API에는 OCR용 파일 또는 Base64를 넣지 않는다. 미리보기 `Blob URL`은 취소,
닫기, 재선택, 컴포넌트 해제 시 폐기한다. 기존 접수 증빙사진은 사용자가 별도
입력에서 선택한 경우에만 기존 비공개 사진 저장 경로로 전송한다.

기존 서버 OCR 엔드포인트는 요청 본문을 처리하기 전에 `410 BROWSER_OCR_ONLY`로
종료하므로 이전 클라이언트가 OCR 원본을 서버에 보내 처리하는 흐름도 사용할 수 없다.

## 정확도 보강

해상도, 밝기, 대비, 흐림, 반사, 암부 비율을 OCR 전에 검사한다. 운영 화면에는
점검요청일, 지역, 지점, 점검작업업체, 매체구분, 고객주소만 자동 입력하고 사용자가
저장 전에 확인·수정한다. OCR 원문과 상세 파싱 결과는 서버 또는 DB에 저장하지 않는다.
이관사유·TAP/RN·전주번호·인입선길이·사전조치·점검요청내용은 완료 전 증빙사진으로
확인하며 OCR 성공 건은 6개 항목 확인 체크 없이는 저장할 수 없다.

영문 학습데이터도 `/ocr/lang/eng.traineddata.gz`에서 자체 제공하며 CDN을 호출하지
않는다. `MHz`, `dB`, `dBmV`, `MER`, `BER`, `ONU`, `RFOG`, `CABLE` 등은
한글 전체를 치환하지 않고 영문·숫자 토큰 문맥에서만 표준 표기로 보정한다.

## 운영상 제한 및 다음 검증

2026-08-28 제공된 화면 촬영 사진(1072×1436)으로 브라우저 실검증했다. 전체 OCR
신뢰도는 86%였다. 결과 표시까지 확인한 측정값은 최초 약 9.7초, 동일 사진 즉시
재실행 약 16.5초였으며 단말 CPU 부하에 따라 달라질 수 있다. `HNS화성지점`, `오산화성`, 요청자,
`2026-08-25`, 주소, `신호점검`, `CABLE`, 사전조치내용은 자동 입력됐다.
화면 모아레가 강한 하단의 빈 측정값 템플릿(측정주파수/상·하향 레벨/MER)은
자동입력 대상이 아니며 증빙사진에서 확인한다. 취소 후 OCR 사진과 브라우저의
인식 결과가 모두 제거되는 것도 확인했다.

기본 임계값은 `quality.ts` 한 곳에서 조정 가능하다.
PaddleOCR.js 공식 브라우저 패키지는 한국어 내장 모델을 제공하지 않아 채택하지 않았다.
향후 Paddle 한국어 ONNX 모델을 직접 준비할 경우에도 라이선스, 브라우저 용량,
저사양 단말 처리시간과 실제 표본 정확도를 확인하기 전에는 운영 기본 엔진으로 전환하지 않는다.
